### Root-cause assessment

1. **Mini Python:** the live backend is serving the pre-fix parser behavior. It tokenizes `for`, `in`, `range`, indentation, and `print`, but rejects those statements with `PY_UNEXPECTED_TOKEN`. The local working tree contains parser/lexer changes and regression tests for this exact pattern, and the same input passes locally. This is a production revision/deployment mismatch, not a newly reproduced local parser defect.
2. **Mini C:** the live backend likewise serves a revision that does not accept the required include/function/nested-loop program. The current local parser accepts the same pattern with a complete tree and zero diagnostics. This is also a production revision/deployment mismatch.
3. **Groq:** the first UI attempt returned a sanitized rejection, but a direct request and immediate UI retry succeeded with HTTP 200 and `openai/gpt-oss-20b`. No stable provider defect can be established from the available evidence. The likely issue is transient or request/deployment state; server-side safe logs would be required to identify the first rejection's upstream cause.
